# 交付清單 — 給一般使用者的東西

要讓一般使用者自己把這套資安長跑起來、插到他的 agent 上，你需要交付四類東西：
**程式包、他要自己準備的、你要先幫他填好的、文件**。

---

## A. 程式包（你打包給他）

整個 repo 目錄，但**排除**以下（這些是本機產物 / 機密，不能給）：

| 排除 | 為什麼 |
|---|---|
| `.env` | 內含這台機器產生的 `GATEWAY_MASTER_KEY` 等機密（他跑 `dciso setup` 會自己重產） |
| `.venv/` | 本機開發用的 Python 環境，正式跑不需要 |
| `.run/` | 執行期 PID / log |
| `.tools/opa` | 本機測試用（正式用容器內的 OPA） |
| `*.sqlite` / `audit-data` volume | 稽核資料，是使用者自己的 |
| `.git/`（可選） | 給 tar / zip 時通常不需要 |

打包指令範例：

```bash
cd ~/Desktop
tar --exclude=.env --exclude=.venv --exclude=.run --exclude=.git \
    --exclude='.tools/opa' --exclude='*.sqlite' \
    -czf dciso-gateway.tgz dciso-governance-gateway/
```

裡面**必須**包含：`bin/dciso`、`docker-compose.yml`、`docker-compose.ciso-hermes.yml`、
`.env.example`、`policy/`、`gateway/`、`ciso-advisor/`、`pep/`、`viewer/`、
`mock-llm/`、`ciso-hermes/`、`hermes/`、`hermes-hook/`、`docs/`、各 `Dockerfile`。

---

## B. 使用者要自己準備的（只有這些是「他的資料」）

| 項目 | 說明 | 沒有的話 |
|---|---|---|
| **Docker Desktop / Docker + Compose v2** | 跑整套 stack | 無法啟動 |
| **一個模型端點（三選一）** | agent 的「業務」模型 | 無法得到真實回覆 |
| ├ 區網 / 本機 Ollama | 一個網址（如 `http://192.168.x.x:11434`）+ 模型名（如 `gpt-oss:120b`） | — |
| ├ OpenAI 金鑰 | `sk-...` | — |
| └ Nous / xAI 登入 | 走 `hermes proxy` | — |
| **他的 agent** | Hermes（要先裝好），或任何 OpenAI 相容用戶端 | 沒東西可治理 |
| **一次性網路** | 第一次 `dciso up*` 會從 ghcr.io 拉映像檔 | 拉不到映像檔 |

> 機密（金鑰）由使用者在自己機器上填進 `.env`，你**不要**代填、也不要放進程式包。

---

## C. 你要先幫他調好的：政策（`policy/data.json`）

程式包附的是通用預設值。交付前依他的環境調這幾塊（其餘可先不動）：

| 區塊 | 要確認 / 調整的 |
|---|---|
| `path_policy.workspace_roots` | 他的專案根目錄（設了之後，寫到範圍外 → 需人工審核）；不設 = 不限制 |
| `path_policy.denied_markers` | 是否要加他環境特有的敏感路徑 |
| `egress_policy.approved_model_markers` | 若他有「公司核准」的模型端點，把 model id 特徵放進來 |
| `egress_policy.route_mode_dest_class` | 確認他的 route mode 對應到正確的 local / approved / external |
| `output_policy.forbidden_markers` / `egress_policy.forbidden_markers` | 他們公司的禁揭露字樣（如「機密」「限內部使用」的實際用語） |
| `egress_policy.sensitive_field_markers` | 他們資料裡的敏感欄位名（身分證、病歷、帳號…） |
| `tools.deny` / `tools.review_required` | 他的 agent 實際會用到、但預設沒列到的工具名 |

改完不用重打包，使用者端 `docker compose restart opa` 即生效（OPA 有 `--watch`）。

## E. 一頁快速開始（可直接貼給使用者）

> 前提：已裝好 Docker Desktop；有一個 Ollama 網址和模型名。

```bash
# 1. 解壓、進目錄
tar -xzf dciso-gateway.tgz && cd dciso-governance-gateway

# 2. 產生設定（會自動產生你的 gateway 金鑰，存在本機 .env）
./bin/dciso setup

# 3. 把你的 Ollama 網址寫進 .env（改這一行）
#    OLLAMA_BASE_URL=http://192.168.47.77:11434

# 4. 啟動治理閘道（資安長用快速的規則引擎；治理任何 agent）
OLLAMA_BASE_URL=$(grep ^OLLAMA_BASE_URL .env | cut -d= -f2) \
  ./bin/dciso up-ollama gpt-oss:120b --ciso rule --agent generic

# 5a. 如果你用 Hermes：一鍵插入（治理一份設定複本，原本的不動）
./bin/dciso plug --clone
#    之後在另一個視窗：  HERMES_HOME=~/.hermes-governed hermes

# 5b. 如果你用其他 agent（Cursor / Aider / LangChain / OpenAI SDK…）：
#    把它的 base_url 設成  http://127.0.0.1:4000/v1
#    把它的 api key 設成   .env 裡的 GATEWAY_MASTER_KEY
#    並移除原本的 provider 金鑰

# 6. 打開治理看板
open http://127.0.0.1:8900        # Linux: xdg-open

# 停止 / 拔除
./bin/dciso unplug --clone        # 還原 Hermes 設定
./bin/dciso down                  # 停止 stack（保留稽核）
```

驗證有在治理：叫 agent 做一件危險的事（例如「讀 ~/.ssh 裡的私鑰」），應該被擋，
看板出現一列 DENY。

---

## F. 一句話回答「我要提供什麼資料」

**你提供**：程式包（不含 `.env`）＋ 調好的 `policy/data.json` ＋ `docs/快速開始.md`。
**使用者提供**：Docker、一個模型端點（Ollama 網址+模型名／OpenAI 金鑰／登入）、
他的 agent。金鑰一律由使用者在自己機器上填進 `.env`，你不碰。
